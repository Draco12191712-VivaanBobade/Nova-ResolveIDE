# Contributing to Nova Resolve IDE

Thank you for your interest in contributing to Nova Resolve IDE. We welcome contributions of all kinds, including code, documentation, bug reports, feature requests, themes, extensions, and improvements to existing functionality.

## Code of Conduct

By participating in this project, you agree to be respectful and constructive. We aim to create a friendly, inclusive, and welcoming community for everyone.

## Before You Start

Before making significant changes, please:

1. Search existing issues and discussions.
2. Check whether your idea or bug has already been reported.
3. Open an issue for large features or architectural changes before starting work.

This helps avoid duplicate work and allows the community to discuss ideas before implementation.

## Ways to Contribute

You can contribute by:

- Fixing bugs.
- Implementing new features.
- Improving documentation.
- Writing tests.
- Creating themes.
- Developing extensions.
- Improving accessibility.
- Reporting issues and providing feedback.
- Reviewing pull requests.

## Development Principles

Nova Resolve IDE is built around the following principles:

- Extensibility first.
- Cross-platform compatibility.
- High performance.
- Clear and maintainable code.
- Accessibility and usability.
- Open collaboration.
- Backward compatibility whenever possible.

## Getting Started

Clone the repository:

```bash
git clone https://github.com/Draco12191712-VivaanBobade/Nova-ResolveIDE.git
```

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Run tests:

```bash
npm test
```

Build the project:

```bash
npm run build
```

## Branches

Please create a new branch for your work:

```text
feature/my-feature
fix/my-bug-fix
docs/update-readme
refactor/improve-parser
```

Avoid committing directly to the main branch.

## Coding Standards

- Use TypeScript whenever possible.
- Write clear and descriptive names.
- Keep functions focused and maintainable.
- Prefer readability over cleverness.
- Follow the existing code style.
- Add comments only when they improve understanding.
- Remove unused code and dependencies.

## Commits

Use descriptive commit messages.

Examples:

```text
feat: add extension manager
fix: resolve file tree refresh issue
docs: improve installation instructions
refactor: simplify project loading logic
```

## Pull Requests

Before submitting a pull request:

- Ensure the project builds successfully.
- Run tests and verify they pass.
- Update documentation when necessary.
- Keep pull requests focused on a single topic.
- Explain the purpose of your changes.

Pull requests may receive feedback or requested changes before being merged.

## Extensions and Themes

Extensions and themes should:

- Be stable and maintainable.
- Avoid unnecessary dependencies.
- Respect user privacy.
- Clearly document configuration options.
- Follow the extension API guidelines.

Authors may choose their own licenses for extensions and themes.

## Reporting Bugs

When reporting bugs, please include:

- Operating system.
- Browser or platform.
- Nova Resolve version.
- Steps to reproduce.
- Expected behavior.
- Actual behavior.
- Screenshots or logs, if applicable.

## Feature Requests

Feature requests should describe:

- The problem being solved.
- The proposed solution.
- Possible alternatives.
- Additional context, if relevant.

## Security

Please do not publicly disclose security vulnerabilities.

Security issues should be reported privately according to the instructions in `SECURITY.md`.
